## 文档职责

本文把 CLI 的**用户级（global）配置存储位置**从 Libra home（`~/.libra/config.db`）迁到平台一致的 XDG 配置目录（`<XDG_CONFIG_HOME 或 ~/.config>/libra/config.db`，macOS 同），并让全域 vault unseal key 与之同域；同时为已存在的用户数据提供一次性、可验证、可回退的自动迁移。

目标是：新用户与现有用户最终都只使用 `<config dir>/libra/config.db`；旧库在首次使用时被安全复制过去并原样保留作为备份；`LIBRA_HOME` 与升级/安装状态维持现状；三处重复的路径解析收敛为单一事实源；文档与测试不再钉死旧路径。

### 适用范围

- 用户级配置作用域（`ConfigScope::Global`）的路径决议、打开/创建、级联读取与写入。
- `LIBRA_CONFIG_GLOBAL_DB` 覆写语义（保持不变）；`XDG_CONFIG_HOME` 的采纳（仅绝对路径）。
- 旧路径 `~/.libra/config.db` 的回退读取与首次使用自动迁移（含锁、快照、校验、原子提交、失败语义）。
- 全域 vault unseal key：`~/.libra/vault-unseal-key` → `<config dir>/libra/vault-unseal-key`（0600）。
- 用户级 hooks 文件路径对齐：`dirs::config_dir()/libra/hooks.json` → 同一配置目录（macOS 读旧位置作为兼容回退）。
- 同步：`docs/commands/config.md` EN + zh-CN、`docs/development/commands/config.md`、`docs/development/account.md`、`docs/commands/init.md` EN + zh-CN、`docs/development/commands/init.md`、`COMPATIBILITY.md` 的 `config` 行、`../libra-backend` 网站对应页、`docs/error-codes.md`（仅在文案/示例需要时）。

### 非目标

- **不改** system 作用域 `/etc/libra/config.db`（及 `LIBRA_CONFIG_SYSTEM_DB`）：XDG 不适用于机器级配置。
- **不改** per-repo 存储：`.libra/libra.db`、`.libra/vault.db`、`~/.libra/vault-keys/<repo-id>`（每仓库密钥属仓库状态，不是用户级配置；不迁移、不改路径）。
- **不改** `~/.libra` 作为 `LIBRA_HOME` 的角色：`bin/`、`env`、`env.fish`、`seccomp.bpf`、`upgrade/`、`tmp/` 全部留在原处。
- **不改** SQLite schema、migration ledger、稳定错误码：本次是文件位置迁移，不是 schema 迁移（GC-13 只要求角色与隔离证明）。
- **不新增** `libra config migrate-global` 显式子命令（策略 A 自动迁移已覆盖；DEFER-GCX-01 保留重启条件）。
- **不做** 旧文件的自动删除/覆盖：迁移后旧文件永久保留，用户自行决定何时清理。
- **不做** `XDG_DATA_HOME`/`XDG_STATE_HOME` 的全面 XDG 化（cache/state 另议）。

### 成功定义

- 新用户：`HOME=$(mktemp -d) libra config set --global user.email a@b.c` 只创建 `<HOME>/.config/libra/config.db`，不创建 `<HOME>/.libra/config.db`。
- 现有用户：仅有 `~/.libra/config.db` 时，首次任何 global 配置访问都把它安全复制到 `<config dir>/libra/config.db`；旧文件字节不变；后续命令只读写新文件；`libra config doctor --global-schema` 报告迁移来源与两份路径。
- 迁移幂等：重复执行/并发执行不产生第二次写入，不损坏任一份数据。
- 失败安全：迁移失败时读取回退旧库并有可操作警告，写入 fail-closed 报可操作错误；旧库永不被修改或删除。
- 全域 vault：unseal key 迁移到 `<config dir>/libra/vault-unseal-key` 后，迁移前写入的加密值仍可解密（不轮换密钥）；旧 key 文件保留为备份。
- `LIBRA_CONFIG_GLOBAL_DB` 覆写行为与测试隔离语义完全不变；`~/.libra/vault-keys/<repo-id>` 与 `tmp/` 位置不变。
- 三处重复解析器消失，`rg` 零命中 `join(".libra").join("config.db")`（测试与迁移模块内除外，且登记 allowlist）。
- 全部非延后卡 `Lifecycle=done` 且 `Acceptance=complete`；全量收口门全绿。

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-GCX-01: 目标目录、解析优先级与 macOS/Windows 口径

- **Status:** Accepted（2026-09-19 用户裁决）
- **Context:** 当前默认 `~/.libra/config.db`；用户要求迁到 `.config/libra`，并明确「macOS 也用 `~/.config/libra`」而不是 `dirs::config_dir()` 的 `~/Library/Application Support`。
- **Decision:**
  1. 新增唯一解析器（放 `src/internal/config.rs`，其余两处调用它）：
     - `LIBRA_CONFIG_GLOBAL_DB` 非空 → 精确使用该文件路径（**不迁移、不读 legacy**，测试/沙箱语义不变）；
     - 否则 `XDG_CONFIG_HOME` 为**绝对路径**时 → `<XDG_CONFIG_HOME>/libra/config.db`；相对路径按 XDG 规范忽略（debug 日志）；
     - 否则 `dirs::home_dir()` → `<home>/.config/libra/config.db`（Linux/macOS/Windows 统一，Windows 为 `%USERPROFILE%\.config\libra\config.db`）；
     - home 不可得 → `None`（现状语义：global 不可用）。
  2. legacy 路径独立函数：`<home>/.libra/config.db`。
  3. 选择「活动路径」的规则（GCX-01 阶段，不做迁移）：
     - 新路径存在 → 用它；
     - 新路径不存在且 legacy 存在 → **用 legacy**（读+写同一文件，避免状态分裂）并在 stderr 输出一次性迁移预告（`--quiet`/`--json` 抑制，JSON 以字段暴露）；
     - 两者都不存在 → 新路径（首次写入时创建）。
  4. system 作用域不变（`/etc/libra/config.db`）。
  5. **保留目录强度**（`is_global_libra_home`）：XDG config 目录与 legacy `<home>/.libra` 目录按「等值或位於其內」保留（`libra init` 不得在用戶配置目錄內建立倉庫）；`LIBRA_HOME`（含 `LIBRA_CONFIG_GLOBAL_DB` 父目錄的隔離約定）僅按等值保留，因為隔離/沙箱場景允許在該目錄下放置倉庫。
- **Alternatives considered:** `dirs::config_dir()`（macOS 会落到 Application Support，与用户裁决相反，拒绝）；Windows 用 `%APPDATA%`（与「统一 `.config`」冲突，拒绝）；不采纳 `XDG_CONFIG_HOME`（偏离 XDG，拒绝）。
- **Consequences:** 新用户数据落在 `~/.config/libra`；`~/.libra` 不再承载 global 配置；旧用户在 GCX-02 前仍读写旧库。
- **Revisit when:** 上游 `dirs` 行为变化，或产品改为「各平台原生目录」。

### ADR-GCX-02: legacy 回退与首次使用自动迁移（策略 A）

- **Status:** Accepted（2026-09-19 用户裁决）
- **Context:** 现有用户数据在 `~/.libra/config.db`（含 `user.*`、`vault.*`、`auth.token.*`、`upgrade.*` 等）。用户选择「首次使用自动迁移」。
- **Decision:**
  1. 触发点：任何 global 配置连接的获取（读或写）之前；条件为「env 覆写未设置 ∧ 新路径不存在 ∧ legacy 存在」。
  2. 迁移成功后：新路径成为唯一读写目标；legacy 文件**原样保留**（备份，不重命名、不删除）。
  3. 两库并存：新路径优先，不自动合并；doctor 报告 legacy 存在并给出手工清理提示。
  4. 新路径存在但损坏/不可读：按现有 Configuration 政策失败，**不**静默回退 legacy（避免双源）。
  5. legacy 存在但不可读/不是配置库：不迁移；读取失败保持现状错误，doctor 归类。
  6. 迁移失败：读路径回退 legacy（本次调用）并给可操作警告；写路径 fail-closed（错误说明目标路径、原因、`LIBRA_CONFIG_GLOBAL_DB` 兜底），绝不写坏旧库。
- **Alternatives considered:** 显式 `migrate-global` 命令（用户选择自动，登记 DEFER-GCX-01）；永久只读回退（状态分裂，拒绝）；硬切（丢失用户数据视图，拒绝）。
- **Consequences:** 首次命令多一次拷贝耗时；`doctor`/`path` 必须暴露迁移状态；旧二进制仍可读旧库（迁移保留备份）。
- **Revisit when:** 需要「用户在升级前预迁移」或 CI 幂等脚本时（DEFER-GCX-01）。

### ADR-GCX-03: 迁移引擎（锁、快照、校验、原子提交）

- **Status:** Accepted
- **Context:** SQLite 库可能带 `-wal`/`-shm`；多进程可能同时触发；迁移必须不破坏源库。
- **Decision:**
  1. **锁**：在目标目录建 `<config dir>/libra/.config.db.migrate.lock`，unix 用 `libc::flock(LOCK_EX)`（随 `client_storage.rs:235-270` 先例），Windows 用零共享句柄失败映射；两端均需 `create_dir_all` 目标目录。若平台无法实现阻塞 flock，退化为 `create_new` 锁文件 + 陈旧锁超时回收；拿锁后**重新探测**新路径是否已被并发迁移创建。
  2. **快照**：对 legacy 以**只读连接**（`mode=ro`，绝不打开为可写）执行 `VACUUM INTO '<目标目录>/config.db.migrate.<pid>.<rand>.tmp'`（SQLite 官方一致性快照，合并 WAL）。2026-09-19 本机 SQLite 3.53.4 已验证 `file:legacy.db?mode=ro` 下 `VACUUM INTO` 成功（exit 0）；实施时断言 bundled libsqlite3-sys 版本 ≥ 3.27，低于或拒绝时改用 `sqlite3_backup` 等价接口，仍不得写入源库。
  3. **校验**：打开临时库断言 `PRAGMA integrity_check = ok`；断言 `configuration_schema_versions` 行与 legacy 一致；断言 `config_kv` 行数一致（键集合可选比对）；断言 `DatabaseRole::GlobalConfig` 的 Configuration 政策可接受。
  4. **提交**：`fs::rename(tmp, new)`（同目录原子），unix 额外 fsync 目录；临时文件在任何失败路径清理；成功路径幂等（新路径已存在即 no-op）。
  5. **角色/隔离（GC-13）**：不新增/推进 migration receipt，不创建 Repository 表；repo 侧命令不得触碰本迁移，反之亦然。
  6. **并发**：持锁者负责迁移；非持锁者等待后重新解析活动路径（不重复迁移）。
- **Alternatives considered:** `fs::copy` + 复制 `-wal`（竞态、易漏，拒绝）；`sqlite3_backup`（需引 extra 接口，`VACUUM INTO` 已足够，拒绝）；迁移进临时目录再跨目录 rename（跨设备可能失败，拒绝）。
- **Consequences:** 迁移期间有短暂锁；旧库保持可回退；`VACUUM INTO` 要求 SQLite ≥3.27（sea-orm/libsqlite3-sys 满足，实施时断言）。
- **Revisit when:** 目标目录与 legacy 不同文件系统且要求零拷贝，或需要跨设备方案。

### ADR-GCX-04: 全域 vault unseal key 随迁

- **Status:** Accepted（2026-09-19 用户裁决「vault 也搬过去」）
- **Context:** 全域加密值（`vault.*`、`auth.token.*`）由 `~/.libra/vault-unseal-key`（32 字节，0600）加密；密钥丢失即不可解密，**绝不能轮换**。
- **Decision:**
  1. 新路径 `<config dir>/libra/vault-unseal-key`（父目录 0700，文件 0600）。
  2. 读取顺序：新文件存在 → 用它；否则 legacy 存在 → 复制到新路径（原子：临时文件 + 0600 + rename），校验 32 字节后使用；否则按现状生成新密钥。
  3. 两份并存且内容不同 → **fail-closed**：报可操作错误并列出两个路径（禁止静默轮换）；内容相同 → 用新路径。
  4. `~/.libra/vault-keys/<repo-id>`（每仓库密钥）与 `~/.libra/tmp` **不动**；在 `docs/development/account.md` 明示边界。
  5. 不修改、不删除 legacy key 文件。
- **Alternatives considered:** 密钥留在 `~/.libra`（与「vault 随迁」裁决相反，拒绝）；密钥放 keyring（范围外，DEFER）；轮换密钥（不可解密既有值，拒绝）。
- **Consequences:** `account.md` 的威胁模型与存储表、`auth.rs`/`vault.rs` 模块注释同步；迁移后既有 token 仍可解密。
- **Revisit when:** 引入 OS keyring 或 `core.symlinks` 式可配置密钥位置。

### ADR-GCX-05: `LIBRA_HOME` 与 global config 路径解耦

- **Status:** Accepted
- **Context:** `resolve_libra_home()` 规则 2 把 `LIBRA_CONFIG_GLOBAL_DB` 的父目录当作 Libra home；若保留，显式覆写的测试/sandbox 仍能隔离升级状态。默认路径改为 XDG 后，默认情形不经过该规则（因为规则只在 env 设置时触发），但语义必须写清楚。
- **Decision:**
  1. `LIBRA_HOME`（缺省 `~/.libra`）继续定义 `bin/`、`env`、`seccomp.bpf`、`upgrade/`、`tmp/` 的位置。
  2. 规则 2 保留但**仅适用于显式设置 `LIBRA_CONFIG_GLOBAL_DB` 的隔离场景**（测试/沙箱），并在模块注释与 dev 文档写明「这是隔离约定，不再是默认布局描述」。
  3. `install.sh` / `install.ps1` 的 `LIBRA_HOME` 语义不变。
  4. 新测试 fixture 在需要隔离升级状态时显式设置 `LIBRA_HOME`（`ConfigDbFixture` 增加该变量），避免依赖规则 2。
- **Alternatives considered:** 删除规则 2（会让只设 `LIBRA_CONFIG_GLOBAL_DB` 的沙箱写到真实 `~/.libra/upgrade`，拒绝）；把 upgrade 也搬去 XDG（范围外，拒绝）。
- **Consequences:** `upgrade::home` 的文档与测试更新；`is_global_libra_home` 同时覆盖 `LIBRA_HOME`、XDG 配置目录与 legacy 目录。
- **Revisit when:** 安装器改为 XDG 布局（`~/.local/bin` 等）。

### ADR-GCX-06: `config path` / `doctor` 的 JSON 契约

- **Status:** Accepted
- **Context:** `doctor` 目前 `path_source ∈ {LIBRA_CONFIG_GLOBAL_DB, home}`、`report_version: 1`；消费者（含 compat 测试）钉住该值。
- **Decision:**
  1. `path_source` 取值保持 `LIBRA_CONFIG_GLOBAL_DB` 不变，新增 `xdg`（用了 `XDG_CONFIG_HOME`）、`home`（`<home>/.config` 默认）、`legacy`（回退旧库）。**不删除、不重命名**既有值。
  2. `report_version` 保持 `1`（纯增量字段）；新增 `legacy_path`、`legacy_exists`、`migration_pending`。
  3. `libra config path --json` 增加同样的 `source`/`legacy_*` 字段；人读输出仍打印活动路径（`--verbose` 时附 legacy 与来源）。
  4. 迁移失败的警告走 stderr，`--quiet`/`--json` 下抑制人读警告，只保留字段/错误码。
- **Alternatives considered:** 提升 `report_version: 2`（会无谓地要求消费方升级，拒绝）；把 `home` 改成 `xdg-default`（破坏已有断言，拒绝）。
- **Consequences:** `tests/compat/global_config_schema_future_test.rs` 与文档同步新增字段；旧消费者不受影响。
- **Revisit when:** 需要破坏性重命名字段（那时再升 `report_version`）。

### ADR-GCX-07: 用户级 hooks 文件路径对齐

- **Status:** Accepted
- **Context:** `load_hook_config()` 的 user tier 走 `dirs::config_dir()/libra/hooks.json`；macOS 与新的 config 目录不一致。
- **Decision:**
  1. 改用 ADR-GCX-01 的同一配置目录：`<config dir>/libra/hooks.json`。
  2. macOS 上保留**只读**兼容回退：新位置缺失时读 `dirs::config_dir()/libra/hooks.json`（存在则加载并 warning 提示迁移），**不写**旧位置。
  3. Linux 下两者本就同路径，无行为变化。
- **Alternatives considered:** 迁移（rename/copy）hooks 文件（用户手工文件，自动改写风险大于收益，拒绝）；不改（macOS 分裂，拒绝）。
- **Consequences:** hooks 文档与测试更新；`compat_agent_*` 守卫不受影响。
- **Revisit when:** 用户要求统一迁移用户级 hooks 文件。

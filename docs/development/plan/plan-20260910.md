## 文档职责

本文规划将 Libra 的 SQLite migration 从「任意连接均使用 `builtin_migrations()`」改为按数据库角色选择 migration registry/ledger，并先阻断 global/system config 的污染路径。`2026090801` 已知是 origin/main 的 forward-only convergence barrier，但当前 `0.22.16` build 的 manifest 最高仅为 `2026090601`，且用户 DB 没有唯一 writer PID 归因；因此它是 **known producer, unsupported by this build, ineligible for automatic repair**。只有取得该 producer revision、attestation 和旧/新 binary oracle 后，才允许进入受确认 repair。目标是：仓库专属 schema 演进不能再阻断全局配置读取或远端同步；真正的配置 schema 不兼容仍然 fail-closed；任何历史库修复均为显式、可备份、可审计的前滚操作。

本文只规划任务，不宣称实现完成。落地时每个任务必须先刷新源码、测试、模板和用户文档锚点，再按任务卡验收。

### 适用范围

- `src/internal/db.rs`、`src/internal/db/migration.rs` 的连接、schema compatibility、migration registry 与 ledger 选择。
- `src/internal/config.rs`、`src/utils/client_storage.rs`、`src/cli.rs`、`src/command/config.rs` 的 global/system config 连接路径、诊断与受确认的历史库修复。
- `sql/migrations/`、`tests/db_migration_test.rs`、`tests/compat/global_config_schema_future_test.rs` 以及共享测试环境隔离。
- `docs/development/plan/plan-template.md` 的永久迁移准则，以及本计划实际触及的用户/开发文档、兼容矩阵、错误码和网站文档。

### 非目标

- 不读取、导出、覆盖、删除或手工编辑真实 `~/.libra/config.db` 的配置值或凭据；开发与验证一律使用隔离 fixture。
- 不把 `0.22.16` 的二进制反向修改为支持未知新格式；当前 `2026090801` 个案只能安装其 producer 所匹配的新版二进制，或在用户已持有的已验证备份上执行灾难恢复。
- 不把 Derived database、publish D1 或 repository data-model 的无关演进重构为本计划的一部分。
- 不在没有已验证旧二进制 oracle、备份与原子事务的情况下承诺修复任意历史 global config DB；不满足条件的个案停在 `DEFER-MIG-01`。

### 成功定义

- 每项 runtime migration 都有显式 `DatabaseRole` allowlist；Repository、GlobalConfig/SystemConfig、Derived 的 schema compatibility 和 migration receipt 不再共享「最高 builtin version」语义。
- repo-only migration 打开或升级 repository DB 时，不改变隔离 global-config DB 的 migration receipt 或 config/config_kv 语义。
- `pull`、`push`、`fetch`、`clone`、`cloud` 只会在 **配置角色** 的真正 future schema 时以 `LBR-CONFIG-001` fail-closed；无关 repository receipt 不再造成误阻断。
- 对观测到的 `2026090801`，doctor 分别报告已知 convergence producer、由运行 build 的 role manifest 计算的支持状态，以及独立的 repair eligibility；没有完整 attestation 时保持 ineligible。它不属于自动 repair 承诺。只有 producer revision 已证明且显式确认的候选库才允许前滚 repair，失败保持原库不变。
- 模板的 GC-13 成为后续所有 schema/connection/fixture 计划的强制准则；本计划的任务、测试、文档、发布与 Claude Code 最终 `VERDICT: PASS` 证据齐全后才可完成。

## 评审结论与修订记录

计划成稿前已完成基于当前源码的自审；Claude Code 审查结果必须写入下方的独立日志，且最终必须为字面 `VERDICT: PASS`。

| 维度 | 结论 | 修订动作 |
|---|---|---|
| 合理性 | 高优先级：真实用户全局库被无关 receipt 推进可阻断同步 | 采用 role-scoped registry，而非教用户手工改数据库 |
| 可行性 | 现有 registry、compat guard、config command path 和隔离 fixture 均有明确落点 | 按测试隔离→registry/bootstrap→写入路由→policy→diagnosis→attested repair 的 DAG 实施 |
| 任务卡粒度 | 7 张卡各自只处理治理、隔离、registry、写入路由、policy、只读诊断或确认式修复一个恢复轴 | 生产卡均为 M；门族 waiver 仅用于不可拆的 doctor/repair fixture 清单 |
| 依赖与顺序 | 无环；MIG-00/01 先于生产变更，MIG-06 最后 | 见实施顺序和 DEP 表 |
| 完整性 | 包含 migration、旧/新兼容、故障注入、docs、release、远端证据 | 每卡写明 migration/rollback 和 ER-06a 判定 |
| 安全性 | 全局 config 可能含凭据；误放行和误写都不可接受 | 只隔离 fixture、secret-free 输出、默认只读 doctor、确认+备份 repair |
| 功能正确性 | 关键风险是 ledger 角色混淆及 legacy repair 错删 receipt | 独立 ledger、manifest allowlist、old-binary oracle、原子事务 |
| 接口兼容 | `LBR-CONFIG-001` 的真实 future-schema fail-closed 契约必须保留 | MIG-04 保留稳定码/JSON 字段，并扩展判定 fixture |

## 已决议设计决策

### ADR-MIG-01: migration registry、receipt 与兼容检查按数据库角色分离

- **Status:** Accepted
- **Context:** 当前 `establish_connection()`、schema inspector 和 upgrade runner 对任意 DB 路径使用一个 builtin registry/最高版本。全局配置数据库只需要配置相关表，却可被 repository operation/worktree migration receipt 推进并被旧客户端拒绝。
- **Decision:** 引入显式 `DatabaseRole::{Repository, GlobalConfig, SystemConfig, Derived}`，由一个 role-aware schema manifest 为每项 migration、fresh bootstrap DDL 与 non-migration idempotent top-up 声明 allowlist。`Repository` 继续使用现有 repository receipt；`GlobalConfig` 与 `SystemConfig` 使用独立的 configuration receipt/registry，只登记 configuration schema 实际需要的 DDL；`Derived` 不得经过 runtime schema writer。新 role-aware open、inspect、upgrade 和 create API 必须显式接收 role；兼容期保留的 generic wrapper 固定为 `Repository`，且不得被 config callsite 调用。禁止根据路径字符串猜测 role。每一 role 的 latest/current 比较只使用自己的 registry/ledger。
- **Alternatives considered:** 保留单一 registry、只让 CLI 忽略 future receipt——拒绝：会将真正不兼容的 config schema 静默用于远端凭据/存储配置。仅向旧 binary 添加例外——拒绝：不能修正新连接继续错误写入的问题。以路径前缀自动猜 role——拒绝：`LIBRA_CONFIG_GLOBAL_DB`/system override 与 test fixture 使路径不是可靠语义。
- **Consequences:** 新 migration、bootstrap 或 top-up 增加时必须标注 role allowlist，并同时覆盖每个受影响 role。当前 generic receipt 不会被新 global-config reader 当作 configuration compatibility 的唯一事实；历史 conversion 由 ADR-MIG-02 的显式 repair 处理。
- **Revisit when:** `SystemConfig` 获得与 `GlobalConfig` 不同的 schema、或引入新的持久化 database role 时。

### ADR-MIG-02: 历史 global-config receipt 只经确认式前滚 repair 处置

- **Status:** Accepted
- **Context:** 已观察到 global config DB 的 generic receipt 高于安装 binary。`2026090801` 的 origin/main convergence semantics 已知，但 user DB 的唯一 writer PID 未建立归因；该 receipt 还高于当前 build 最大 `2026090601`。直接删 receipt、覆盖 SQLite 文件或自动 downgrade 都可能损失未知状态，且会破坏 fail-closed 安全边界。
- **Decision:** 提供 `libra config doctor --global-schema` 的只读诊断，输出 receipt、known-convergence / unsupported-by-build disposition 与非敏感 file metadata。只有 `--repair --confirm <canonical-config-db-path>` 可执行 repair，且只有 DEP-MIG-02 提供完整 source/binary attestation 的 receipt 才可能 eligible。repair 必须在目标锁定后重做资格核验，校验 canonical target，用 role manifest 判定每个 receipt，以 SQLite backup API 或等价 SQLite-consistent 方法建立可重开验证的 backup，并在单个 SQLite transaction 中初始化 config-specific ledger 和转换允许 receipt；unattested receipt、表 fingerprint 不符、备份/锁/事务失败都不写库并给出稳定、secret-free 诊断。repair 的资格必须同时由固定旧 binary/source oracle 证明，不能用“看起来无关”代替。
- **Compatibility window:** configuration-owned legacy-reader barrier is a compatibility migration: MIG-04 uses the user-mandated `patch + 1` release increment plus `forward-only`, and its release gate must prove the pinned old reader rejects the barrier before any write while the same-build Config-role reader accepts it. Version numbering does not authorize downgrade or rollback.
- **Alternatives considered:** 打开 config DB 时自动修复——拒绝：用户全局凭据库不应由普通读取隐式改写。让用户用 sqlite 手改 schema_versions——拒绝：不可审计且易数据损失。永久保留 generic receipt 并要求所有旧版本升级——拒绝：不能阻断在 configuration schema 未变化时的可验证兼容窗口。
- **Consequences:** `2026090801` 在完整 attestation 到手前保持阻断并进入 `DEFER-MIG-01`；本计划不把它写成可 repair。repair 只前滚到清晰的双-ledger 模型。文档必须明确备份位置、恢复步骤、不可自动 repair 的情形和安装 producer-matched binary 的升级路径。
- **Revisit when:** 固定 0.22.16 oracle 无法获得或发现 config DB 中有额外 role-coupled state 时；此时停止 repair 实施，不放宽 allowlist。

本计划继承 `plan-template.md` v2.4 的 GC-01..GC-13 全文，尤其是 GC-07（fail-closed）、GC-08（原子性与恢复）、GC-09（隔离与资源生命周期）、GC-12（精确暂存）和 GC-13（role-scoped migration/ledger、global config fixture isolation、禁止手改 receipt）。以下为本计划附加约束。
